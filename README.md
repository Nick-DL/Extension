# 排班辅助插件 (Scheduling Helper Extension)

绵阳市第三人民医院 · 科室排班辅助填表工具 — 浏览器扩展（Manifest V3）

## 功能概述

在排班系统页面（`http://10.66.66.151/app/attendance/schedules/hospital`）注入“排班辅助”浮窗，覆盖数据加载、排班编辑、冲突处理到统一提交的完整流程。

1. **五步排班向导**：人员 → 门诊 → 特殊 → 值班 → 确认
2. **工作周切换**：上一周 / 下一周 / 指定周跳转，切换后自动重新加载对应周数据
3. **上周数据导入**：门诊与值班顺序均可根据上周数据重建，先预览冲突再应用
4. **自动排班**：8 位置值班轮转、门诊冲突检测、白班1快速分配、一键填空、规培生同步导师排班
5. **页面表格双向同步**：插件排班结果渲染到系统表格，页面手动修改也会同步回插件；支持单格/两段排班模式
6. **统一提交保护**：启用期间拦截页面排班写请求，由插件统一批量提交
7. **备份恢复 / 配置导入导出**：启用时自动备份；门诊与完整排班配置支持 JSON 导入导出
8. **测试模式**：可为额外测试环境页面注册动态 content script

## 安装方法

### 开发模式安装

1. 打开 Chrome 浏览器，进入 `chrome://extensions/`
2. 开启右上角 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择 `Extension` 文件夹，扩展安装完成
5. 打开排班系统页面，插件会自动启用并打开浮窗

### 图标

图标文件已随项目提供（`icon.svg`、`icon48.png`、`icon128.png` 及 Material Icons 字体），无需额外生成。

### 测试模式

正式排班系统地址已默认包含在 `manifest.json` 的 content script 匹配中。其他测试环境页面可在扩展弹窗中：

1. 打开“测试模式”开关
2. 输入 URL 匹配模式（例如 `http://localhost/*`）
3. 点击“添加测试页面”，随后刷新目标页面生效

## 使用流程

### 1. 启用插件

- 打开排班系统页面，插件会自动启用、加载数据并打开浮窗
- 关闭浮窗后，可点击页面右侧“排班辅助”快捷入口重新打开
- 也可在扩展弹窗中查看当前工作周、人员与班型信息，并手动开启/关闭
- 启用时会自动开启“两段排班”模式，并备份当前数据

### 2. 五步排班流程

| 步骤 | 内容 | 说明 |
|------|------|------|
| 1. 人员 | 工作周切换、人员列表、导师绑定、工作日设定 | 切换周后自动重载数据；规培生需指定导师 |
| 2. 门诊 | 总院/高新/梓潼/简易门诊 | 支持导入上周门诊预览、冲突提示与 JSON 导入导出 |
| 3. 特殊 | 产假/事假/培训/开会等 | 按医生批量勾选时段并应用类型 |
| 4. 值班 | 值班序列 + 自动排班 | 8 位置轮转、拖拽排序、导入上周顺序、冲突检测 |
| 5. 确认 | 冲突处理 + 补缺 + 提交 | 白班1分配、周末门诊检查、一键填空、规培同步 |

### 3. 提交修改

- 在步骤 5 点击“提交所有修改到系统”
- 提交前会再次同步页面上的手动修改，然后分上午、下午两批提交
- 提交成功后可按提示刷新页面查看结果

## 页面表格同步

插件会识别页面排班表为“单格模式”或“两段排班模式”，把插件中的排班结果以文本和班型色条形式渲染到对应单元格。

同时监听表格变化：在系统表格中手动修改班型后，插件会防抖同步回内部状态；总院门诊同一时段多人时会自动归入简易门诊。常用班次区域的班型标签也会按班型颜色自动配色。

启用期间插件还会拦截页面直接发出的排班写请求、锁定工作周选择器，避免绕过插件造成数据不一致。

## API 接口参考

### 数据读取

| 接口 | 用途 |
|------|------|
| `GET /api/biz/attendance/att_employee` | 获取员工列表 |
| `GET /api/biz/attendance/empSchedules` | 获取员工排班数据 |
| `GET /api/biz/attendance/att_class` | 获取班型列表 |
| `GET /api/biz/attendance/att_schedule_location` | 获取院区列表 |
| `GET /api/biz/attendance/scheduleGroupEmps` | 获取排班组成员 |
| `GET /api/biz/attendance/empScheduleReport` | 获取排班报表数据 |

### 数据写入

| 接口 | 用途 |
|------|------|
| `POST /api/biz/attendance/schedule/employee` | 批量提交排班（核心写入接口） |
| `POST /api/biz/attendance/appendUsualClass` | 批量清除排班（`classId` 传 `null`） |
| `POST /api/biz/attendance/updateScheduleMemo` | 保存班次备注 |
| `POST /api/biz/attendance/employeeDisplayOrder` | 保存人员显示排序 |

### 请求格式

```json
// POST /api/biz/attendance/schedule/employee
{
  "ids": null,
  "schedules": [
    {
      "empId": "员工ID",
      "workDate": "2026-07-13",
      "classId": 10,
      "locationId": 1,
      "deptId": 5
    }


  ]
}
```

上午时段的 `workDate` 为 `YYYY-MM-DD`；代码中下午时段使用 `S` 前缀（如 `S2026-07-13`）区分，具体以系统接口约定为准。

## 排班规则

### 自动排班

值班序列为 8 个位置，依次对应：`(上周日值班)周一夜休 → 周一值班·周二夜休 → 周一中班·周二值班·周三夜休 → ... → 周六中班·周日值班`，按序列顺序自动填入中班、值班、夜休。

- 已有安排不会被覆盖；科主任、规培生、培训中或休假中人员不进入值班池
- 节假日时，白班普、白班1、中班自动转为“休”
- 可勾选“假期前一天取消中班”

### 冲突检测

1. 上午高新/梓潼门诊 + 下午值班 → 上午冲突，建议安排白班1或手动处理
2. 上午高新/梓潼门诊 + 下午中班 → 下午冲突，建议安排白班1或手动处理
3. 上午总院门诊 + 下午值班 → 上午冲突，建议安排白班1或手动处理
4. 下午总院门诊 + 下午中班 → 下午冲突，建议安排白班1或手动处理
5. 中班医生当天上午已有总院门诊 → 自动跳过上午中班，不标记冲突
6. 下午总院门诊 + 值班 → 自动跳过下午值班，不处理

页面手动设置白班1后，对应时段的冲突提示会自动消除。

### 人员分类

- **医疗**：系统排班类别为“医疗”的医生
- **规培**：人员类别为“规培协议/规培生”等规培人员
- **其他人员（如护理）**：不进入插件，不会被修改

## 技术栈

- Manifest V3
- 纯 JavaScript（无框架依赖）
- Content Script + Background Service Worker + Popup
- 页面主世界 `bridge.js`：复用页面 Cookie / Token 的 fetch 代理
- `chrome.storage.local` 状态持久化
- Ant Design DOM + React Fiber 周切换

## 注意事项

1. **两段排班模式**：插件逻辑依赖该模式，启用后会自动开启并禁止手动关闭
2. **页面 DOM 结构**：表格定位、周选择器等基于 Ant Design；系统界面升级时需同步调整 `content.js`
3. **班型名称映射**：`classMap` 依赖 `att_class` 返回的班型名称，名称变化会影响解析与配色
4. **API 响应结构**：代码已兼容 `rows` / `list` / `employees` 等常见返回结构，如实际接口变化需调整 `lib/api.js`
5. **恢复备份**：恢复的是插件启用时的状态快照，已提交到系统的数据请刷新页面查看
